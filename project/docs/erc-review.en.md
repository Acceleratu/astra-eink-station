# Review of power pins flagged by Fusion ERC

The final ERC capture contains 35 warnings with code 104. Each identifies a pin declared as `pwr` whose name differs from the name of the connected net. For each row, the table traces the pin through the device library in `schematic/astra.sch` to the assigned land and verifies the net assigned to that land in `board/astra.brd`. The ID column retains the `object_id` from the Fusion capture. Sheet numbers refer to the released schematic. The component, pin and net still identify the connection if the symbol moves. ## Cross-check against the native design files

The 35 ID entries have been preserved. Between the comparison capture and the final ERC, 34 out of the 35 component/pin/net triples are identical. At ID 1, U101.IN_HV transitioned from PV_IN to PV_IC_IN via populated bridge resistor R126. D102.1 and R126.2 are on PV_IN, while U101.20, C103.1, R105.1, and R126.1 appear together on the new network in both the schematic and PCB. Fusion includes the sheet and coordinates in the native `signature` string. The literal comparison preserved 22 signatures. Of the 13 modified signatures, 12 have only changes in position or sheet. Signature ID 1 includes the new network name. For ID 0–2, U101 moved from sheet 2 to sheet 3. For ID 8–12, U104 moved from sheet 3 to sheet 2. For ID 3–5 and 13–14, U102 and U105 only changed their coordinates on the same sheet. The before-and-after signature pairs appear in the numeric result. The checker confirmed all 35/35 symbol → land → net mappings on the PCB. The 35 final entries have `code=104`, `type=1` and `state=0`. The schematic has no stored ERC approvals and no other errors or warnings. Physical checks still pending include power under load, solder joints on hidden contacts, continuity and behavior during power-source switching.
